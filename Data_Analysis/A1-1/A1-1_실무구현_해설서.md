## 3. 객체지향 파이프라인 심층 해설 (`src/pipeline.py`)

### 3.1 데이터 로드 및 날짜 파싱 (`load_data`)
```python
self.df = pd.read_csv(csv_path)
if "order_date" in self.df.columns:
    self.df["order_date"] = pd.to_datetime(self.df["order_date"])
if img_path and os.path.exists(img_path):
    self.images = np.load(img_path)
```
- 문자열로 된 날짜 컬럼을 `pd.to_datetime`으로 변환하여 이후 시계열 집계와 Recency 일수 계산이 가능하도록 만듭니다.

### 3.2 NumPy 벡터 연산 기반 이미지/텍스트 특성 추출 (`extract_multimodal_features`)
**평가 핵심**: 파이썬 `for` 반복문 없이 배열 축(axis) 연산만으로 계산해야 합니다.

```python
# (1500, 64, 64, 3) 텐서에서 axis=(1, 2, 3)으로 이미지별 전체 픽셀 평균/표준편차 단번에 계산
img_mean_all = np.mean(self.images, axis=(1, 2, 3))
img_std_all = np.std(self.images, axis=(1, 2, 3))

# 채널별 평균: axis=(1, 2) -> 결과 shape: (1500, 3)
img_channel_means = np.mean(self.images, axis=(1, 2))
self.df["img_r_mean"] = img_channel_means[indices, 0]
self.df["img_g_mean"] = img_channel_means[indices, 1]
self.df["img_b_mean"] = img_channel_means[indices, 2]
```
- 텍스트는 `str.len()`(글자 수)과 `str.split().str.len()`(어절 수)을 사용해 피처를 추출합니다.

#### 3.2.1 벡터 연산은 항상 더 빠른가? — 실측 벤치마크
**실측 환경**: 1,500 × 64 × 64 × 3 uint8 (17.6MB), 동일 데이터 5회 반복 **최솟값**

| 구현 | 시간 |
| :--- | ---: |
| `np.mean(axis=(1, 2, 3))` 평균만 | 7.6 ms |
| `np.mean` + `np.std(axis=(1, 2, 3))` (현재 코드) | 71.7 ms |
| `reshape(N, -1)` 후 `axis=1` 평균+표준편차 | 57.4 ms |
| float32로 변환 후 `reshape` + `axis=1` | 45.9 ms |
| 파이썬 `for` 루프 (이미지별 `.mean()/.std()`) | 58.6 ms |
| 채널별 `np.mean(axis=(1, 2))` | 117.2 ms |

- **결론**: 벡터화가 "루프 제거"만으로 항상 빠른 것은 **아닙니다**. 평균+표준편차 조합은 위 표에서 루프(58.6 ms)와 비슷하고,
  채널별 `axis=(1, 2)` 연산은 오히려 **가장 느립니다**(117.2 ms).
- **내부 이유 (메모리·하드웨어)**
  - NumPy `ndarray`는 **연속 메모리 버퍼**에 고정 크기 dtype으로 배치되어 CPU의 SIMD(AVX2/AVX-512, NEON) 명령으로 한 사이클에 여러 값을 처리하고,
    캐시 지역성(Spatial Locality)을 확보해 L1/L2 캐시 미스를 줄입니다.
  - 그런데 uint8 배열을 `np.mean`/`np.std`로 줄이면 내부 누적 dtype이 **float64로 승격**되어 8배 메모리 대역폭을 사용합니다.
  - `axis=(1, 2)`처럼 **마지막 축(채널 3)을 남기는** 연산은 stride가 3으로 건너뛰는 비연속 접근이 되어 SIMD 활용이 떨어집니다.
  - `reshape(N, -1)`로 **한 축으로 펼치면 연속 접근**이 보장되어 평균+표준편차가 71.7 → 57.4 ms로 빨라집니다.
- **본 구현의 선택**: 1,500건 기준 차이는 10~20 ms 수준이므로 정확도(float64 누적)와 가독성을 우선해 `axis=(1, 2, 3)` 구현을 유지했습니다.
  수만~수십만 장으로 늘리면 아래 3.2.2의 병목 대상을 참고해 연속 축 + float32로 전환하는 것이 맞습니다.

#### 3.2.2 대규모 이미지 처리의 병목과 대응
| 병목 | 원인 | 대응 |
| :--- | :--- | :--- |
| 메모리 사용량 | 10만 장 × 64×64×3 uint8 ≈ **1.14 GB** (float32 변환 시 4.6 GB) | `np.load(mmap_mode="r")`·배치 처리·다운샘플링 |
| I/O | 대용량 `.npy`/이미지 파일 일괄 로드 | 배치 로더, 포맷 변환(JPEG→memmap), 캐싱 |
| CPU | 단일 스레드 누적 연산 | `multiprocessing`/`joblib` 병렬화, 연속 축 + float32 |
| 정확도 손실 | 평균을 위한 표본 축소 | 층화 샘플링 후 전체 데이터로 통계 재추정 |

### 3.3 그룹별(GroupBy) 결측치 대치 알고리즘 (`handle_missing_values`)
단순 전체 평균으로 결측치를 채우면 "10대 전자기기 구매자"의 나이가 "전체 평균 나이(35세)"로 왜곡됩니다.
```python
# 카테고리별 중앙값 대치
group_stats = self.df.groupby(group_col)[target_col].transform("median")
self.df[target_col] = self.df[target_col].fillna(group_stats).fillna(overall_stat)
```
- `transform("median")`을 사용하면 원본 데이터프레임의 인덱스 형태를 그대로 유지하면서 각 행의 카테고리에 해당하는 중앙값으로 결측치가 대치됩니다.
- **부작용과 선택 기준 (중요)**: 그룹별 대치는 편향을 줄이는 대신 **분산을 축소**합니다.
  예를 들어 어떤 그룹의 결측 5건이 모두 같은 중앙값(41세)으로 채워지면 그 5건은 서로 완전히 동일한 값이 되어, 해당 그룹의 분산은 실제보다 작아지고
  상관계수·표준편차가 과소평가될 수 있습니다. 반대로 표본이 적은 그룹의 극단적인 중앙값이 적용되면 **그룹 간 차이가 과장**되는 방향으로도 왜곡됩니다.
  - 완화 방법: (1) 그룹 표본 수가 작으면 전체 대표값으로 폴백(`fillna(group_stats).fillna(overall_stat)` 구현이 이 역할),
    (2) 결측 여부를 `*_is_missing` 파롟 컬럼으로 남겨 정보를 보존, (3) 결측률이 10%를 넘으면 MICE/KNN 같은 다중 대치 검토.
  - 본 데이터는 결측이 59건(3.9%)·34건(2.3%)으로 작아 그룹 중앙값 대치의 영향이 제한적입니다.

### 3.4 IQR 사분위수 이상치 탐지 및 클리핑 (`detect_outliers`)
```python
q1 = float(np.percentile(series, 25))
q3 = float(np.percentile(series, 75))
iqr = q3 - q1

lower_bound = q1 - (iqr_multiplier * iqr)
upper_bound = q3 + (iqr_multiplier * iqr)
is_outlier = (self.df[column] < lower_bound) | (self.df[column] > upper_bound)
```
- 정규분포를 따르지 않는 비대칭 이커머스 매출 데이터는 평균과 표준편차($3\sigma$) 대신 중앙값 기반의 $IQR$ 기법을 사용해야 왜곡 없이 정확한 이상치 경계선을 그을 수 있습니다.
- `np.clip`을 적용해 이상치를 데이터에서 삭제(Drop)하지 않고 상한선으로 눌러주어(Clipping) 데이터 손실을 방지합니다.
- **IQR의 한계**: IQR은 비대칭 분포에서 $3\sigma$보다 안정적이지만 만능이 아닙니다.
  - **정상 고가 거래를 이상치로 분류**: 극단적 비대칭(롱테일)에서는 $Q_3 + 1.5\,IQR$이 낮게 잡혀 정상 거래가 대량 포함됩니다.
    실제로 본 데이터의 탐지 162건 중 Electronics가 102건(해당 카테고리 335건의 30%)이고, 클리핑으로 사라지는 금액은 전체 결제액의 29.0%입니다.
  - **경계 불안정**: $Q_1, Q_3$에만 의존하므로 표본이 작거나 값이 이산적이면(수량형) 경계가 튑니다.
  - **다봉 분포**: 서로 다른 정상 군집 사이를 이상치로 볼 수 있습니다.
- **보완책**: (1) 카테고리별로 IQR을 따로 계산, (2) **위저라이징(Winsorizing)** — 상·하위 $p\%$를 분위값으로 대체(본 `np.clip`도 넓은 의미의 위저라이징),
  (3) 로그·Box-Cox 변환 후 적용, (4) Isolation Forest·LOF 같은 다변량 기법. 분포를 정리하는 것이 목적이면 클리핑, 매출 합계를 보존해야 하면 원본 `amount`를 유지하는 것이 맞습니다.

### 3.5 RFM 고객 세분화 및 분위수 스코어링 로직 (`calculate_rfm`)
- **기준일($T_{ref}$)**: 데이터 최종 거래일 + 1일
- **지표 집계**:
  - $R$ (Recency): $T_{ref} - \max(\text{order\_date})$ (작을수록 최근 구매)
  - $F$ (Frequency): 고객별 주문 건수 (클수록 우수)
  - $M$ (Monetary): 고객별 결제 총액 (클수록 우수)
- **점수화 (`_percentile_score`)**:
  - 각 지표를 **평균 순위(average rank) 백분위**로 변환한 뒤 4분위 경계로 1~4점을 부여합니다.
  - `rank(method="first")` + `qcut`은 동점자를 임의 순서로 잘라 점수군을 무조건 25%씩 강제 분할하므로,
    실제 빈도 분포와 무관한 라벨이 붙습니다(예: 1회 구매 고객이 F_score=2를 받을 수 있음). 본 구현은
    **동점자에게 동일 점수**를 주고 점수군 크기는 **데이터 분포를 그대로 반영**합니다(25%가 아닐 수 있음).
  - $R$은 `ascending=False`로 역순 매핑하여 최근일수록 높은 점수를 받습니다.
- **5대 세그먼트 규칙 매핑** (위에서부터 먼저 만족하는 조건에서 확정 = 순서가 곧 우선순위):
  1. `VIP`: R, F, M 모두 상위권 ($R \ge 3 \land F \ge 3 \land M \ge 3$)
  2. `New`: 최근 방문 + 실제 주문 1건 ($R \ge 3 \land \text{frequency} = 1$)
  3. `Loyal`: 구매 경험이 많고 최근에도 방문 ($R \ge 3 \land (F \ge 2 \lor M \ge 2)$)
  4. `At_Risk`: 과거 고가치 고객이나 최근 미방문 ($R \le 2 \land (F \ge 3 \lor M \ge 3)$)
  5. `Churned`: 전 지표가 낮은 완전 이탈군
- **순서가 중요한 이유**: `New`를 `Loyal` 뒤에 두면 `Loyal` 조건이 먼저 참이 되어 `New`가 **도달 불가능한 세그먼트**가 됩니다.
  따라서 `New` 판정을 `Loyal` 보다 앞에 두고, 판정 기준도 F 점수가 아닌 **원시 주문 건수**로 두어 "최초 구매 고객"의 의미를 보존했습니다.
- **왜 4분위(1~4점)인가**: 세그먼트 규칙의 임계값과 점수 스케일을 일치시키기 위해서입니다.
  - 규칙은 `≥3`(상위 2개 구간)을 "우수", `≤2`를 "저조"로 판정합니다. 4분위에서는 경계가 정수로 딱 떨어져 규칙표를 그대로 읽을 수 있습니다.
  - 5분위라면 중간(3점) 구간이 어중간해져 "상위/하위" 판정을 규칙표로 쪼개기 어렵습니다.
  - 3분위 이하는 세그먼트가 성기고, 10분위 이상은 해석이 어려워집니다. 즉 **4분위는 규칙 기반 세그먼테이션과 해석 가능성의 타협점**입니다.
  - 점수군 **크기**는 데이터 분포에 따라 달라지며(동점자 동일 점수), 4분위는 "경계 설계"만 고정합니다.

## 5. 데이터 기반 비즈니스 인사이트 도출 3단계 공식

체크리스트 요구사항을 완벽히 만족하기 위해 **(근거) - (실행) - (검증)** 구조로 기술합니다.

1. **(근거 - Evidence)**:
   - 추상적인 서술이 아닌 명확한 수치(예: "VIP 28.7%가 총 매출 53.8% 견인", "단가 상관 0.74")를 제시합니다.
   - 단, `amount = unit_price × quantity`처럼 **정의상 성립하는 상관**은 발견으로 제시하지 않고 산식과 함께 서술합니다.
2. **(실행 - Action)**:
   - **대상(Target)** + **실행 방법(Action)** + **기대 효과(KPI Impact)**를 구체적인 마케팅/운영 전략으로 정의합니다.
3. **(검증 - Validation)**:
   - 이 가설을 입증하기 위해 **추가로 필요한 데이터**(예: 웹 세션 로그, 상품별 마진율)와 가설이 틀렸을 가능성인 **반증 가능성**(예: 체리피킹, 수요 선반영)을 1문장 이상 반드시 기술합니다.
