### 1. AI 서비스 기획의 전체 생명주기: 푸드트럭 창업 프로젝트
AI 프로젝트를 진행하는 것은 단순히 "비싼 오븐(초거대 AI 모델)"을 하나 장만하는 일이 아닙니다. 손님이 줄을 서서 맛있게 먹고 결제까지 마치는 **성공적인 푸드트럭 식당을 여는 과정**과 똑같습니다.

```
[푸드트럭 창업 5단계]
1. 시장 조사 & 메뉴 선정 ──▶ 2. 주방 & 서빙 동선 설계 ──▶ 3. 조리법 연구 ──▶ 4. 트럭 포장 & 오픈 ──▶ 5. 시식회 & 피드백
 (문제 정의 & 타겟 고객) (시스템 아키텍처 설계) (AI 모델 개발) (Docker & 서빙 API) (최종 발표 & 데모)
```

1. **아이디어 발굴 & 문제 정의**: "강남역 직장인들이 점심시간에 15분 만에 건강한 샐러드를 먹고 싶어 한다(Pain Point)"를 발견합니다.
2. **요구사항 정리**: "키오스크로 주문받고 3분 안에 조리 완료(기능/비기능 요구사항)"를 결정합니다.
3. **주방 설비(모델) & 홀 매니저(API 서버) 구축**: AI 모델이 요리사라면, 주문을 받아 요리사에게 전달하고 음식을 손님에게 건네는 매니저(API 서버)가 필요합니다.
4. **밀키트 포장(Docker 컨테이너화)**: 어느 축제 장소에 가든 트럭 전원만 꽂으면 똑같이 작동하도록 주방 도구와 재료를 박스 하나에 완벽히 패키징합니다.
5. **시식회(데모 & 발표)**: 심사위원과 고객 앞에서 매끄럽게 음식을 서빙하고 박수를 받습니다.

### 3. 기능 요구사항(FR) vs 비기능 요구사항(NFR): 맛있는 버거 vs 3분 안에 나오는 버거
- **기능 요구사항 (FR, Functional Requirements)**: 
 - "이 서비스가 무엇을 할 수 있는가?"
 - 예: 영수증 사진을 업로드하면 글자를 인식(OCR)하고 총금액을 계산해야 한다.
- **비기능 요구사항 (NFR, Non-Functional Requirements)**: 
 - "그 기능을 얼마나 빠르고, 안전하고, 튼튼하게 수행하는가?"
 - 예: 사용자가 사진을 올린 후 **2초 이내**에 인식 결과가 화면에 떠야 한다. 동시에 50명이 접속해도 서버가 뻗지 않아야 한다.

### 우선순위 정하기 (MoSCoW 법칙)
프로젝트 마감일은 항상 촉박합니다. 모든 걸 다 만들려다간 마감 전날 밤을 새워도 데모가 터집니다.
- **Must Have (필수)**: 이게 없으면 서비스 자체가 성립 안 됨 (예: 카메라로 사진 찍어 분류하기).
- **Should Have (중요)**: 있으면 너무 좋지만, 정 급하면 2차 배포로 미룰 수 있음 (예: 소셜 카카오 로그인).
- **Could Have (있으면 좋음)**: 시간 남으면 넣는 예쁜 애니메이션 효과나 다크 모드.
- **Won't Have (이번엔 포기)**: 아이디어 회의 땐 나왔지만 이번 학기 팀 프로젝트 범위에서 과감히 제외할 항목.

### 4. 시스템 아키텍처: 레스토랑의 역할 분담
- **프론트엔드 (손님이 보는 식탁과 메뉴판)**: 웹 브라우저나 스마트폰 화면(React, Streamlit, Flutter).

- **데이터베이스 (냉장고 창고)**: 손님 주문 내역, 회원 정보, 로그 기록 보관.

### 5. Docker: 어디서든 그대로 돌아가는 마법의 컨테이너 상자
내 노트북에서는 잘 돌아가던 파이썬 코드가 팀원 컴퓨터나 클라우드 서버에 올리면 "라이브러리 버전이 안 맞다", "CUDA 경로가 없다"며 에러를 뿜어냅니다.
Docker는 파이썬 버전, 라이브러리, 환경설정 파일까지 **통째로 하나의 밀폐된 캡슐(컨테이너)**에 담아버립니다. 윈도우든 맥이든 리눅스든 버튼 하나로 1초 만에 완벽히 똑같은 환경이 실행됩니다.

### 6. 모델 경량화: 무거운 트럭을 날렵한 스포츠카로 개조하기
- 훈련을 막 마친 딥러닝 모델은 수억 개의 정밀한 소수점 숫자(32비트 실수)로 채워져 있어 용량도 기가바이트(GB) 단위이고 반응 속도도 느립니다.
- **양자화(Quantization)**: 소수점 셋째 자리까지 깐깐하게 따지던 정밀도(FP32)를 0부터 255 사이의 정수(INT8)로 과감히 다이어트시킵니다. 맛(정확도)은 1% 미만으로 거의 안 떨어지면서 주방 서빙 속도(추론 속도)는 3~4배 빨라집니다.

## 2. 요구사항 정의서 명세 체계 (FR vs NFR Matrix)

### 2.1 요구사항 분류 기준
- **기능 요구사항 (FR)**: 입력 $X$에 대해 시스템이 수행해야 하는 비즈니스 변환 로직 $f(X) \to Y$.
- **비기능 요구사항 (NFR)**: 서비스 가용성(Availability), 처리 속도(Latency, Throughput), 확장성(Scalability), 보안(Security).

### 2.2 실무 요구사항 정의서 예시 테이블
$$\begin{array}{c|c|c|c|c}
\hline
\textbf{Req ID} & \textbf{분류} & \textbf{요구사항 설명 (Specification)} & \textbf{우선순위 (MoSCoW)} & \textbf{검증 기준 (Acceptance Criteria)} \\
\hline
\text{FR-01} & \text{비전} & \text{이미지 업로드 시 바운딩 박스 검출 및 다중 객체 분류} & \text{Must} & \text{mAP@50 } \ge 0.85 \\
\text{FR-02} & \text{NLP} & \text{검출된 텍스트 영역에 대한 한국어 요약문 생성} & \text{Should} & \text{ROUGE-1 } \ge 0.40 \\

## 4. FastAPI 기반 고성능 ML 추론 서버 엔드포인트 설계

비동기 I/O와 Pydantic 정적 타입 검증을 결합한 프로덕션 수준의 엔드포인트 구현:

```python
from fastapi import FastAPI, File, UploadFile, HTTPException, Depends, status
from pydantic import BaseModel, Field
import numpy as np
import onnxruntime as ort
from PIL import Image
import io
import time

app = FastAPI(title="AI Vision & NLP Serving Engine", version="1.0.0")

# 1. 전역 세션 로드 (LifeSpan 또는 Startup 이벤트)
session = ort.InferenceSession("model_quantized.onnx", providers=["CUDAExecutionProvider", "CPUExecutionProvider"])
input_name = session.get_inputs()[0].name

class PredictionResponse(BaseModel):
 class_id: int = Field(..., description="Top-1 예측 클래스 인덱스")
 confidence: float = Field(..., ge=0.0, le=1.0, description="소프트맥스 신뢰도 점수")
 inference_time_ms: float = Field(..., description="순수 추론 소요 시간 (ms)")

def preprocess_image(image_bytes: bytes) -> np.ndarray:
 try:
 img = Image.open(io.BytesIO(image_bytes)).convert("RGB")
 img = img.resize((224, 224))
 arr = np.array(img).astype(np.float32) / 255.0
 # ImageNet 정규화: (x - mean) / std
 mean = np.array([0.485, 0.456, 0.406], dtype=np.float32)
 std = np.array([0.229, 0.224, 0.225], dtype=np.float32)
 arr = (arr - mean) / std
 arr = np.transpose(arr, (2, 0, 1)) # HWC -> CHW
 arr = np.expand_dims(arr, axis=0) # NCHW
 return arr
 except Exception as e:
 raise HTTPException(status_code=400, detail=f"Image decoding failed: {str(e)}")

@app.post("/api/v1/predict", response_model=PredictionResponse, status_code=status.HTTP_200_OK)
async def predict_endpoint(file: UploadFile = File(...)):
 if file.content_type not in ["image/jpeg", "image/png"]:
 raise HTTPException(status_code=415, detail="Unsupported media format.")
 
 contents = await file.read()
 tensor_input = preprocess_image(contents)
 
 start_t = time.perf_counter()
 outputs = session.run(None, {input_name: tensor_input})
 latency = (time.perf_counter() - start_t) * 1000.0
 
 logits = outputs[0][0]
 # Softmax
 exp_logits = np.exp(logits - np.max(logits))
 probs = exp_logits / np.sum(exp_logits)
 pred_class = int(np.argmax(probs))
 conf = float(probs[pred_class])
 
 return PredictionResponse(
 class_id=pred_class,
 confidence=conf,
 inference_time_ms=round(latency, 2)
 )

@app.get("/health", status_code=status.HTTP_200_OK)
async def health_check():
 return {"status": "healthy", "engine": "ONNXRuntime"}
```

## 5. Dockerfile 최적화 및 Multi-Stage Build

프로덕션 배포 시 이미지 레이어를 최소화하고 빌드 의존성을 제거하여 경량화된 컨테이너 이미지를 빌드합니다.

```dockerfile
# Stage 1: Build & Dependency Resolution
FROM python:3.10-slim AS builder

WORKDIR /app
RUN apt-get update && apt-get install -y --no-install-recommends \
 build-essential \
 && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir --user -r requirements.txt

# Stage 2: Minimal Runtime Environment
FROM python:3.10-slim AS runner

WORKDIR /app
# 비특권 유저(Non-root User) 생성 (보안 최적화)
RUN groupadd -r appuser && useradd -r -g appuser appuser

# 빌드 스테이지에서 설치된 패키지만 복사
COPY --from=builder /root/.local /home/appuser/.local
COPY --chown=appuser:appuser . .

ENV PATH=/home/appuser/.local/bin:$PATH
USER appuser

EXPOSE 8000
HEALTHCHECK --interval=30s --timeout=5s --retries=3 \
 CMD curl -f http://localhost:8000/health || exit 1

CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000", "--workers", "2"]
```

## 6. AI 모델 최적화 및 경량화 (ONNX & Quantization)

### 6.1 ONNX(Open Neural Network Exchange) 변환
PyTorch 모델을 플랫폼 독립적인 정적 계산 그래프 표준인 ONNX IR(Intermediate Representation)로 직렬화(Serialization):
```python
import torch

model.eval()
dummy_input = torch.randn(1, 3, 224, 224)

torch.onnx.export(
 model,
 dummy_input,
 "model.onnx",
 export_params=True,
 opset_version=14,
 do_constant_folding=True,
 input_names=["input"],
 output_names=["output"],
 dynamic_axes={"input": {0: "batch_size"}, "output": {0: "batch_size"}}
)
```

### 6.2 INT8 양자화(Quantization) 수학적 원리
32비트 부동소수점 $r \in [\alpha, \beta]$를 8비트 정수 $q \in [q_{min}, q_{max}]$ (예: $[-128, 127]$)로 선형 아핀 사상(Affine Mapping):
$$r = S \cdot (q - Z)$$
- **스케일 인자 (Scale factor $S$)**:
 $$S = \frac{\beta - \alpha}{q_{max} - q_{min}}$$
- **영점 (Zero Point $Z$)**:
 $$Z = \text{round}\left( \frac{-\alpha}{S} \right) + q_{min}$$
- **동적 양자화(Dynamic Quantization)**: 런타임에 활성화 텐서의 최소/최대 범위를 동적으로 측정하여 가중치와 곱셈을 8비트 행렬 곱(INT8 GEMM)으로 가속하고 메모리 대역폭을 $75\%$ 절감합니다.

### 7.2 Commit Convention & PR Review 가이드
- **Commit Type**:
 - `feat`: 새로운 기능 구현 (e.g., `feat: implement ONNX export pipeline`)
 - `fix`: 버그 수정 (e.g., `fix: handle empty batch zero division error`)
 - `refactor`: 기능 변화 없는 코드 구조 개선
 - `docs`: README 또는 API 문서 수정
- **PR 템플릿 필수 구성 요소**:
 1. **개요 (What & Why)**: 이번 PR에서 변경된 핵심 아키텍처/로직
 2. **성능 벤치마크 결과**: Latency 변화 ($150\text{ms} \to 45\text{ms}$), 정확도 손실률 여부
 3. **테스트 스크린샷**: Pytest 유닛 테스트 통과 로그 및 API 응답 캡처
 4. **코드 리뷰어 2인 이상의 Approved 승인 후 Merge 규칙 적용**
